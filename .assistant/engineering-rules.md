# Engineering Rules

1. Specify before generating.
2. Never treat silence as permission to expand scope.
3. Architecture precedes substantial construction.
4. Provide 2-3 architecture options for non-trivial decisions.
5. Human owns architecture decisions.
6. Work in manageable blocks.
7. Keep context scoped to the current block.
8. Inspect existing code before adding abstractions.
9. Avoid unrelated refactoring.
10. Every meaningful behavior change needs tests.
11. Every database schema change needs a migration.
12. External APIs require validation, timeout and failure behavior.
13. Never claim tests passed unless executed.
14. Never claim security without checking concrete attack surfaces.
15. Documentation must reflect actual behavior.
16. External audit is adversarial, not confirmatory.
17. Findings are evidence-based and severity-rated.
18. AI/agent tools require explicit permissions and bounded side effects.
19. Report contradictions instead of silently resolving them.
20. Prefer simple architecture unless complexity is justified.
