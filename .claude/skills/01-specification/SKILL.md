# Specification

## Purpose
Define what the system should and should not do before implementation.

## Procedure
Clarify objective, actors, flows, scope, non-goals, data, interfaces, requirements, business rules, errors, acceptance criteria, NFRs, technology constraints and open questions.

## IDs
FR = functional requirement
BR = business rule
NFR = non-functional requirement
AC = acceptance criterion
ERR = error scenario

## Rules
Requirements must be testable. Do not invent business rules. Distinguish assumptions from confirmed requirements.

## Completion gate
A reviewer can explain what the application does, does not do, what data it manages, who uses it and how success is verified.
